# Widgets and Wallpaper share the Themes style

The user requested removal of Widgets' glass presentation and a consistent Themes-based style across Widgets and Wallpaper. The live Themes page was inspected first: dark navy canvas, cyan/violet pooled light, quiet hairline edges, solid rectangular filter surface, compact typography, and restrained pill/floating buttons.

`StudioAtmosphere` now uses the actual `ThemeAtmosphere` renderer, Midnight Aurora lighting and cached backdrop on both pages. Widgets no longer paints the alpine wallpaper across its page. Wallpaper retains its actual full-bleed hero behind floating navigation, then fades into the same Themes atmosphere. This supersedes the wallpaper-color-derived atmosphere from the preceding report.

Widgets defaults to Dark; the Frosted preset is removed from its spotlight choices. Default clock previews use thin cyan/violet edges rather than bright glass outlines. Large live-blurred reflections and moving glow shadows are removed; the stage uses Themes' cached `CardHalo` shadow and static floor light. Neighbors now follow the actual previous/next widget, with pagination and the existing directional movement. Original widget materials remain available in the existing catalog/customizers, and saved desktop widget data is not migrated or overwritten.

`StudioFilterSurface` reproduces Themes' solid surface, radius, hairline and spacing for Widgets and Wallpaper. Search no longer has a separate inner glass capsule. Recommendation/catalog cards use shared design tokens, uniform widths, Themes-style section headings and quiet controls. Add, favorites, size/material selection, customization and catalog scrolling remain; all 91 catalog and 634 themed entries are still included. Wallpaper's media borders are quieter cyan/hairline edges, its library detail sheet is solid navy with a cached shadow, and its heading uses the compact title scale. Primary and secondary navigation are unchanged.

Responsive review caught two issues: Wallpaper's original 52-point heading dominated small windows, and external source selections could be ignored while its view state survived page changes. The heading now uses the shared title scale, and a guarded UI-state observer synchronizes Aerials/Art/My Videos for deep links and the renderer without a feedback loop.

Verification artifacts are in `build/review/studio-theme-style-2026-10-06/`. Final production build, all 334 tests in 86 suites, signature verification and whitespace checks pass with no compiler warnings. The original and final page-render sets are retained separately; the final set covers Themes, Widgets and all three Wallpaper sources at 900×600 and 1280×800. The first Art/video render set incorrectly retained Aerials and was not accepted as source-specific verification; source synchronization was fixed before the final set.

Real-window scroll probes ran the old and new debug executables. Initial Widgets warm CPU: 31.5% before, 32.1% after; p95 18.9 ms in both. A repeat of the final build measured 31.0% warm CPU, p95 18.3 ms, worst gap 26.1 ms. Wallpaper warm CPU: 28.0% before, 15.2% after initially; final repeat 14.2%, p95 18.1 ms, worst gap 18.5 ms. All runs recorded zero gaps above 33 ms. These are local observations, not a controlled guarantee of CPU savings; the user and other apps remained active.

The profiling script also sampled whole-Mac AGX driver utilization and WindowServer CPU during alternating old/new runs. Widgets: WindowServer 38.3% before/44.88% after, median device utilization 11%/32.5%. Wallpaper: WindowServer 42.5%/42.14%, median device utilization 68%/68%. These shared counters include other apps and the probe's nearly invisible window; they do not establish an isolated GPU/WindowServer improvement. Raw samples/statistics and probe logs are retained. The code reduces live blur/shadow work and reuses existing caches, but no unsupported GPU reduction is claimed.
